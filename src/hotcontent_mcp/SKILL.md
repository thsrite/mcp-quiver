# 爆款内容雷达

查三类数据：**全网实时热榜**（85 个榜单）、**公众号爆款文章**（含全文正文）、**小红书爆款笔记**（含互动数据）。

配套的 `hotcontent` MCP 提供 4 个工具。**必须先绑定该 MCP，否则本技能无法取数**——没有工具时不要凭记忆编造榜单内容，直接告诉用户 MCP 未接入。

## 先分清两种数据粒度（最重要）

每个工具的返回都带 `granularity` 字段，它决定你**能说什么、不能说什么**：

| granularity | 工具 | 有什么 | 能回答 |
|---|---|---|---|
| `topic` | `search_hot_topics` | 标题、排名、热度值 | 「现在什么话题在火」 |
| `content` | `search_wechat_articles`、`search_xiaohongshu_notes` | 完整互动数据 + 作者粉丝数 | 「哪条内容爆了、为什么爆」 |

**`topic` 数据没有点赞/收藏/评论数**。用户问「这条爆文点赞多少」而你手上只有 `topic` 数据时，说明这份数据不含互动量，改用另两个工具，不要拿"热度值"冒充点赞数。

## 工具选择

| 用户问什么 | 用哪个 |
|---|---|
| 今天/最近全网什么热点、微博热搜、知乎热榜、B站/抖音在火什么 | `search_hot_topics` |
| 能查哪些平台/网站 | `list_hot_boards` |
| 公众号选题、爆文对标、写作风格分析、10万+ 长什么样 | `search_wechat_articles` |
| 小红书选题、低粉爆款、笔记对标 | `search_xiaohongshu_notes` |
| 某个主题在全网多热 | `search_hot_topics(keyword="主题")`，跨 85 个榜搜 |

**用户说「小红书热榜」时注意**：全网热榜数据源**不含小红书**，要用 `search_xiaohongshu_notes`。

## 各数据源的诚实边界（必须如实告知，不要粉饰）

**全网热榜**（实时）
- 85 个榜单，覆盖微博·知乎·微信·百度·B站·抖音·快手·贴吧·虎扑·36氪·掘金·GitHub·App Store·雪球·豆瓣·懂球帝·FreeBuf 等
- 不含小红书；不含推特、YouTube 等境外平台
- 只有标题和热度值，不同平台的"热度"口径不同（微博是万级、B站是播放量、抖音是播放次数），**不要跨平台直接比大小**

**公众号**（快照，滞后 1-2 天）
- 四榜：低粉爆款 / 10万阅读 / 1万阅读 / 原创榜
- 三个源里唯一有**全文正文**的，做写作风格分析首选
- `read` 字段常见 `"10w+"`，是平台封顶显示，不是精确值；排序更该看 `share`（分享）和 `watch`（在看）
- 冷门关键词可能返回 0 条，如实说"该赛道收录少"，不要换个词假装是原词的结果

**小红书**（快照，滞后 1-2 天）
- 四榜：点赞Top500 / 低粉爆款 / 7日飙升 / 单日飙升
- **没有笔记正文**：`desc` 常为空是数据源本身如此（源 desc 就是"标题+话题标签串"，去标签后 44% 完全为空），不是抓取失败。有价值的是 `tags`
- `link` 缺 xsec_token，用户点开会提示"当前笔记暂时无法浏览"，**提醒用户按标题去 App 内搜**，别让他们空点
- `days` 参数对该源基本不生效

## 输出规范

- **数字只用工具返回的原值**，不要估算、换算或补全。`"10w+"` 就写 `10w+`，不要写成 `100000` 或"约 10 万"
- 引用某条内容时带上它的 `link`（小红书的除外，见上）
- 条数不足用户要求时**如实说少了多少**，禁止用其他关键词或其他榜的内容凑数
- 涉及"今天的数据"：热榜是实时的可以说；公众号/小红书要说明是快照、通常滞后 1-2 天
- 做选题建议时，**低粉爆款榜的价值最高**（几百粉丝拿几万赞的样本 = 选题红利，排除了账号权重因素），优先从这里找

## 典型用法

```
用户「最近有什么热点」        → search_hot_topics(limit=5, max_boards=8)
用户「知乎和微博在聊什么」     → search_hot_topics(platform="知乎,微博")
用户「AI 相关的全网热度」      → search_hot_topics(keyword="AI", max_boards=20)
用户「找职场类公众号爆文对标」  → search_wechat_articles(keyword="职场沟通", limit=10)
用户「分析爆文怎么写的」       → search_wechat_articles(keyword=..., content_len=0) 取全文再分析
用户「小红书穿搭爆款」         → search_xiaohongshu_notes(keyword="穿搭")
```

关键词技巧：**细分词远好于大类词**（「通勤穿搭」>「时尚」，「职场沟通」>「职场」）。用户给的是大类词时，先建议几个细分方向再查。
